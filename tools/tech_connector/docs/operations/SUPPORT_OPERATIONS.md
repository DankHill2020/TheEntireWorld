# Support Operations

Launch requires a monitored support address/portal, a public status location, a
named owner and backup, hours of coverage, response targets, privacy-safe identity
verification, escalation, and incident messaging. Do not ask customers to send
project assets or source files for licensing support.

Document playbooks for email verification, account recovery, organization admin
changes, agreement/acceptance history, license selection, named-seat assignment,
lost-machine deactivation, device-limit disputes, offline expiry, payment/refund,
tax invoice, project registration, Community reporting, Enterprise escalation,
accessibility, and privacy deletion/access requests. Administrative overrides
must be least-privilege, time-bound where possible, reason-coded, and audited.

Publish only support levels the team can actually deliver. Self-service support
needs maintained documentation and a response channel; Enterprise SLAs need
staffing, on-call coverage, exclusions, and service-credit language approved in
the agreement. Define severity consistently and never promise 24/7 coverage
before it exists.

Verification evidence includes working inbound/outbound tests, staffing rota,
escalation contacts, response targets, canned status templates, admin-access
review, and completion of a lost-device plus account-recovery drill.
