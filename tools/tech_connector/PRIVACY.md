# Tech Connector Privacy and Data Handling Notice

Release status: pre-release draft — counsel approval required

Last updated: 2026-09-28

Tech Connector is designed as a local-first production tool. This notice
describes the client behavior implemented in this repository and the minimum
data contract expected of the private licensing service. It is not yet an
approved public privacy policy. The Entire World, LLC must have counsel approve
this notice, add the applicable business contact and jurisdictional disclosures,
and publish the final retention schedule before a production release.

## What remains local

Tech Connector does not upload project assets, source files, scene contents,
animation data, prompts, renders, or other creative work to the licensing
service. A local project path is converted to a random project identifier; the
path itself is not sent during project registration. DCC commands and creative
content remain local unless the user separately configures a cloud model or
another external integration.

The client may store the following locally:

- a cryptographically signed entitlement token and its expiration dates;
- a refresh credential protected by the operating-system credential store;
- a random installation identifier, not a hardware fingerprint;
- random project identifiers and local project-path mappings;
- a readable license-acceptance receipt containing agreement version/time and
  opaque account, organization, license, offer, and verification identifiers,
  but not the raw token or account email; and
- audit events containing timestamps and opaque account, license, project, and
  activation identifiers, but not tokens, email addresses, or project paths.

The acceptance receipt is available from **License Management > Open
Acceptance Receipts** and is stored in the application's licensing-data folder.
It is a local convenience copy; the verified-account licensing service retains
the authoritative acceptance history under its approved access and retention
controls.

## Licensing-service data

Account and licensing operations may send only the data needed to authenticate
and enforce an entitlement:

- verified account identity and organization membership;
- license, agreement, support, version, seat, and device-limit information;
- a pseudonymous installation identifier and activation records;
- random project identifiers and accepted project-term versions; and
- when the user requests private source access, a linked GitHub provider-user
  identifier plus repository-grant, invitation, and reconciliation status; and
- security and operational metadata normally generated by HTTPS services, such
  as timestamps, network address, request outcome, and client version.

Passwords are entered only through the configured browser-based identity
provider and are never collected by the Tech Connector client. Payment data
must be handled by the selected payment provider and must not be placed in an
entitlement token.

GitHub account linking is optional unless the user requests licensed source
access. It occurs in the account portal, not the desktop client. GitHub OAuth
and App credentials remain in private backend infrastructure; the client does
not receive them. GitHub's own privacy and security terms apply to the account,
invitation, repository, and access activity handled by GitHub.

## Offline access and security

The signed entitlement can be cached for its configured offline period, up to
90 days. The client contains public verification keys only. Private signing
keys, backend credentials, payment secrets, and production authentication
secrets must remain in private infrastructure protected by appropriate key
management and access controls.

## Telemetry and optional services

Product analytics or telemetry must be opt-in or separately configured. Cloud
AI providers, source-control services, update services, and other integrations
have their own data practices and are contacted only when configured or used.
Their privacy terms apply to data intentionally sent to them.

## Required completion before release

The final approved notice must identify the data controller and contact method,
purposes and legal bases, production retention periods, subprocessors and
international transfers, regional privacy rights and request procedures,
children's-data position, security-incident contact, and the effective date.
Those policy decisions belong to the production business and private backend;
they cannot be truthfully inferred from this public client repository.
